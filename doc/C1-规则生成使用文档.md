# C1 规则生成使用文档

> 本文是 C1 的专题深入；全项目安装、A4 用例、C5 造数、Mock 与运行模式见
> [AstSight 使用文档](AstSight-使用文档.md)。

| 项 | 内容 |
|---|---|
| 适用能力 | C1 需求分析 / A1 规则抽取 |
| 命令入口 | `astsight rules c1`（等价于 `astsight rules extract`） |
| 输入 | 需求文档（必填）+ 设计文档（可选）+ OpenAPI（可选） |
| 输出 | `ruleset.json` + `ruleset.md` + 上下文与草案目录 |
| 依赖 | Python 运行环境；模型通过环境变量配置 |

## 1. 用途

把需求文档、设计文档和可选的 OpenAPI 契约，转换成可追溯的业务规则库：

- 业务规则 `BR`：从文档原文抽取，必须带章节与原文引用；
- 契约规则 `CR`：从 OpenAPI 确定性提取，不调用模型；
- 冲突 `conflicts`：文档之间或文档内部的矛盾；
- 缺口 `gaps`：文档该写未写、或原文默认成立但未说明的假设；
- 待确认问题 `questions`：需要业务方或外部系统回答的事项。

C1 只产出规则，不生成用例。生成用例属于 A4，规则库是 A4 的输入。

## 2. 前置条件

### 2.1 工作目录

以下命令默认在 `engine/` 下执行：

```bash
cd <repo>/engine
```

如果包已安装到当前 Python 环境，也可以不设置 `PYTHONPATH`；源码目录运行时使用：

```bash
PYTHONPATH=. python -m astsight ...
```

### 2.2 模型配置

`rules c1` 会在框架内调用模型。推荐用配置文件：

```bash
cd engine
cp llm.example.json llm.json     # llm.json 已 gitignore，可用 --llm-config 指定其他路径
```

查找顺序为 `--llm-config PATH` / `ASTSIGHT_LLM_CONFIG` → `./llm.json` →
`~/.astsight/llm.json`；未知字段会直接报错。密钥不要写进命令、脚本或文档：
保持 `api_key` 为空，用 `api_key_env` 指向环境变量。

也可以只用环境变量（覆盖文件值）：

| 用途 | 优先变量 | 兼容变量 |
|---|---|---|
| API Key | `ASTSIGHT_LLM_API_KEY` | `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` |
| Base URL | `ASTSIGHT_LLM_BASE_URL` | `ANTHROPIC_BASE_URL` |
| 模型 | `ASTSIGHT_LLM_MODEL` | `ANTHROPIC_MODEL` |
| 超时 | `ASTSIGHT_LLM_TIMEOUT` | - |
| 最大输出 | `ASTSIGHT_LLM_MAX_TOKENS` | - |

示例（只写变量名，实际值由运行环境提供）：

```bash
export ASTSIGHT_LLM_API_KEY=...
export ASTSIGHT_LLM_BASE_URL=...
export ASTSIGHT_LLM_MODEL=...
```

没有模型环境时，使用第 6 节的两段式流程，由外部模型或人工产出草案。

## 3. 快速开始

### 3.1 需求 + 设计 + OpenAPI

```bash
PYTHONPATH=. python -m astsight rules c1 \
  --project examples/partner_onboarding \
  --requirements examples/partner_onboarding/docs/requirements.md \
  --design examples/partner_onboarding/docs/design.md \
  --openapi examples/partner_onboarding/openapi.json
```

### 3.2 只有需求文档

```bash
PYTHONPATH=. python -m astsight rules c1 \
  --project examples/partner_onboarding \
  --requirements examples/partner_onboarding/docs/requirements.md
```

设计文档和 OpenAPI 都可省略。没有 OpenAPI 时：

- 仍生成业务规则 `BR`；
- 不生成契约规则 `CR`；
- 输出中会出现 `openapi_missing` warning。

### 3.3 多份需求或多份设计

`--requirements` 和 `--design` 都可以重复：

```bash
PYTHONPATH=. python -m astsight rules c1 \
  --project $PROJECT \
  --requirements $PROJECT/docs/requirements.md \
  --requirements $PROJECT/docs/requirements-extra.md \
  --design $PROJECT/docs/design.md \
  --design $PROJECT/docs/api-design.md \
  --openapi $PROJECT/openapi.json
```

### 3.4 只校验，不写规则库

```bash
PYTHONPATH=. python -m astsight rules c1 \
  --project examples/partner_onboarding \
  --requirements examples/partner_onboarding/docs/requirements.md \
  --design examples/partner_onboarding/docs/design.md \
  --openapi examples/partner_onboarding/openapi.json \
  --dry-run
```

注意：`--dry-run` 只是不写 `ruleset.json` 和 `ruleset.md`，模型调用仍然发生，仍会消耗 token。模型草案会保留在上下文目录，便于定位问题。

## 4. 参数

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `--project` | 是 | - | 项目根目录，规则库写到该目录下 |
| `--requirements` | 是，至少一个 | - | 需求文档，可重复 |
| `--design` | 否，可重复 | 空 | 设计文档，与需求一起作为 A1 输入 |
| `--openapi` | 否 | 自动发现 | 契约文件；不传时查找项目内常见 OpenAPI 路径 |
| `--out` | 否 | `.astsight/rules` | 上下文目录，相对 `--project` |
| `--rule-base` | 否 | `ruleset.json` | 规则库路径，相对 `--project` |
| `--max-rules` | 否 | `500` | 单次抽取规则上限，实际限制在 1–500 |
| `--prompt` | 否 | `prompts/a1_requirement_analysis.md` | 覆盖 A1 提示词 |
| `--dry-run` | 否 | `false` | 只校验，不写规则库 |
| `--json` | 否 | `false` | 输出机器可读 JSON |

`--openapi` 不传时，会按以下常见位置自动发现：

```text
openapi.json
openapi.yaml / openapi.yml
docs/openapi.json
api/openapi.json
app/openapi.json
src/main/resources/openapi.json
src/main/resources/openapi.yaml
```

如果项目里存在 `openapi.json`，即使不传 `--openapi` 也会被使用。要确保没有 CR 规则，需要让项目内不存在可发现的 OpenAPI 文件。

## 5. 产物

### 5.1 文件位置

```text
<project>/
├── ruleset.json                         # 机器可读的规则库（唯一真相源）
├── ruleset.md                           # 人工评审文档（从 ruleset.json 渲染）
└── .astsight/rules/<context_id>/
    ├── context.json                     # 文档分节、原文、OpenAPI 摘要
    ├── prompt.md                        # A1 提示词
    ├── rules.schema.json                # 草案输出 schema
    ├── rules.draft.json                 # 模型产出的草案
    └── README.md                        # 本次上下文说明
```

### 5.2 `ruleset.json`

主要字段：

- `ruleset_id`、`version`：规则库标识与版本；
- `rules[]`：业务规则；
- `contract_rules[]`：OpenAPI 契约规则；
- `conflicts[]`、`gaps[]`、`questions[]`：冲突、缺口与待确认问题；
- `documents[]`：输入文档及其哈希；
- `prompt`：提示词版本与模型信息。

规则的关键字段：

- `rule_key`：稳定键，框架生成；
- `rule_id`：展示编号，如 `BR-01`；
- `text`：可判定的规则陈述；
- `constraints`：结构化约束；
- `source`：文档、章节、编号、原文引用；
- `authority`：`A` 或 `B`；
- `fingerprint`：内容指纹，用于 diff。

### 5.3 `ruleset.md`

人工评审视图，包含：

1. 统计；
2. 规则表；
3. 冲突；
4. 定义缺口；
5. 隐含假设；
6. 业务确认清单；
7. 枚举未闭合项。

`ruleset.md` 是只读视图。规则有误时，应修改需求/设计原文后重新生成，不要直接编辑 `ruleset.json` 或 `ruleset.md`。

## 6. 两段式流程（模型在框架外运行）

需要离线批处理、Claude Code Skill、人工审阅草案，或不想让框架直接调用模型时，使用两段式。

### 6.1 生成上下文

```bash
PYTHONPATH=. python -m astsight rules prepare \
  --project examples/partner_onboarding \
  --requirements examples/partner_onboarding/docs/requirements.md \
  --design examples/partner_onboarding/docs/design.md \
  --openapi examples/partner_onboarding/openapi.json
```

输出：

```text
examples/partner_onboarding/.astsight/rules/<context_id>/
```

### 6.2 外部模型写草案

让模型读取：

- `context.json`
- `prompt.md`
- `rules.schema.json`

产出：

```text
<context_id>/rules.draft.json
```

草案必须满足：

- `context_id` 与上下文一致；
- 每条规则的 `source.quote` 是原文精确子串；
- 规则文本中的数字、错误码、反引号内容能在 `quote` 中找到；
- `authority` 只能是 `A` 或 `B`；
- `in/not_in` 必须显式声明 `exhaustive`；
- 冲突、缺口、问题引用真实存在的规则 ID。

### 6.3 导入规则库

先只校验：

```bash
PYTHONPATH=. python -m astsight rules import \
  --project examples/partner_onboarding \
  --context examples/partner_onboarding/.astsight/rules/<context_id> \
  --draft examples/partner_onboarding/.astsight/rules/<context_id>/rules.draft.json \
  --dry-run
```

校验通过后写入：

```bash
PYTHONPATH=. python -m astsight rules import \
  --project examples/partner_onboarding \
  --context examples/partner_onboarding/.astsight/rules/<context_id> \
  --draft examples/partner_onboarding/.astsight/rules/<context_id>/rules.draft.json
```

## 7. 校验与门禁

导入前会执行确定性校验，主要包括：

| 校验 | 说明 |
|---|---|
| 上下文一致性 | `context_id`、文档哈希、提示词哈希必须匹配 |
| 来源可解析 | `source.doc/section/number` 必须能在上下文中定位 |
| 原文落地 | `source.quote` 必须是章节原文的精确子串 |
| 关键 tokens | 规则文本里的数字、错误码、枚举值必须出现在 `quote` 中 |
| 约束取值 | `constraints.values`、`error_code` 必须有原文依据 |
| 权威等级 | 只允许 A/B，C/D 不可作为独立 oracle |
| 枚举闭合 | `in/not_in` 必须声明是否穷尽 |
| 结构约束 | 引用前必须满足；`operator=other` 必须不携带值 |
| 冲突口径 | 冲突必须是“A 说 X，B 说非 X”或明确的分支不可达 |
| schema | 草案必须符合 `rules.schema.json` |

校验失败时：

- 不写 `ruleset.json`；
- 模型原始草案保留在上下文目录；
- 命令返回非 0，并在输出中列出错误。

不要绕过校验去手改规则库。校验失败通常说明文档原文不可判定、引用不精确，或模型超出了原文。

## 8. 重复执行与版本

每次 `rules c1` 都是完整快照：

- 版本号递增；
- 本次未出现的旧规则会进入 diff 的 `deprecated`，不再作为有效规则；
- 已修复的 `questions/gaps/conflicts` 不会残留；
- 文档、OpenAPI 或提示词变化会生成新的 `context_id`。

重跑后应检查：

```bash
PYTHONPATH=. python -m astsight rules status \
  --project examples/partner_onboarding
```

重点看：

- `business_rules` / `contract_rules` 数量；
- `status.active`；
- `questions`、`gaps`、`conflicts`；
- `rule_drift_stale_cases`：已有用例是否引用了过期规则。

## 10. 常见问题

### 10.1 提示模型配置缺失或 401

检查 `ASTSIGHT_LLM_API_KEY` / `ANTHROPIC_AUTH_TOKEN`、`ASTSIGHT_LLM_BASE_URL`、`ASTSIGHT_LLM_MODEL` 是否在当前 shell 生效。不要把密钥写进命令或提交到仓库。

### 10.2 出现 `openapi_missing`

说明没有传入 `--openapi`，项目内也没有自动发现到 OpenAPI。业务规则仍会生成，但不会生成 CR 契约规则。需要 CR 时补 `--openapi`，或把契约文件放到自动发现路径。

### 10.3 校验报 quote 不匹配

通常是草案的 `quote` 不是原文精确子串，或规则文本中的数字/错误码没有出现在引用里。处理顺序：

1. 检查 `context.json` 中对应 section 的原文；
2. 修正草案的 `quote` 或规则文本；
3. 重新 `rules import`。

不要为了过校验去改 `ruleset.json`。

### 10.4 `context_id` 不一致

说明 `prepare` 和 `import` 之间文档、OpenAPI 或提示词发生了变化。重新执行 `rules prepare`，使用新的上下文目录。

### 10.5 `--dry-run` 后没有生成文件

这是预期行为。去掉 `--dry-run` 才会写 `ruleset.json` 和 `ruleset.md`。

### 10.6 只想重新渲染 Markdown

```bash
PYTHONPATH=. python -m astsight rules render \
  --project examples/partner_onboarding
```

默认写到 `ruleset.json` 同目录的 `ruleset.md`。

## 11. 命令速查

```bash
# C1：需求 + 设计 + OpenAPI
PYTHONPATH=. python -m astsight rules c1 \
  --project $PROJECT \
  --requirements $PROJECT/docs/requirements.md \
  --design $PROJECT/docs/design.md \
  --openapi $PROJECT/openapi.json

# 只有需求
PYTHONPATH=. python -m astsight rules c1 \
  --project $PROJECT \
  --requirements $PROJECT/docs/requirements.md

# 只校验
PYTHONPATH=. python -m astsight rules c1 \
  --project $PROJECT \
  --requirements $PROJECT/docs/requirements.md \
  --design $PROJECT/docs/design.md \
  --openapi $PROJECT/openapi.json \
  --dry-run

# 两段式：准备上下文
PYTHONPATH=. python -m astsight rules prepare \
  --project $PROJECT \
  --requirements $PROJECT/docs/requirements.md \
  --design $PROJECT/docs/design.md \
  --openapi $PROJECT/openapi.json

# 两段式：导入草案
PYTHONPATH=. python -m astsight rules import \
  --project $PROJECT \
  --context $PROJECT/.astsight/rules/<context_id> \
  --draft $PROJECT/.astsight/rules/<context_id>/rules.draft.json

# 查看规则库状态
PYTHONPATH=. python -m astsight rules status --project $PROJECT
```

### 1.2 A1b 一致性扫描（新建）

独立调用，**只给规则、不给原文**。核心设计：手里有原文时，模型会用原文把矛盾解释掉。

六个分组维度（前四个靠词面，后两个靠业务流转）：

1. 同一字段 / 表
2. 同一实体
3. 同一动作
4. 同一指标
5. **前提-结论链**：一条规则的结论是否构成另一条的前提
6. **口径链**：同一业务量在计算 → 结算 → 展示三段的规则

四类关系检查：互斥、冗余/算法冲突、空档、失配（数值与作用范围）。

## 2 结果 A：分组覆盖（客观、可复现）

先验证一个前置问题：**如果分组规则根本不会把两条矛盾规则分到一组，后面要求"检查互斥"再多次也没用。**

| 分组维度 | 组数 | 金标准同组覆盖 |
|---|---|---|
| 仅前四个维度（字段/实体/动作/指标） | 63 | **10 / 12** |
| 加后两个维度（前提链/口径链） | 69 | **12 / 12** |

落不进前四个维度的两条，恰好是最难发现的两条：

| 漏掉的 | 为什么词面抓不到 |
|---|---|
| BR-56 / BR-92 / BR-108 分支不可达 | 三条分别讲「跳转」「403」「准入条件」，两两有交集，三者无共同 token；只有把前提串成链才暴露 |
| BR-62 / BR-78 历史数字漂移 | 一条讲「签单数怎么算」，一条讲「档位不追溯」，字面毫不相关；只有沿收益链串起来才暴露 |

**结论：分组维度是这套扫描的瓶颈，不是检查项。** 加一条"请检查互斥"的指令，
不如加一个"按前提链分组"的约束。

## 5 局限（必须说明）

**这不是模型行为回归。** 执行者是我，而我知道金标准答案。因此：

- 「12/12 复现」不能证明换一个模型也能做到，只能证明**判据覆盖了这些问题类型**；
- 真正的盲区验证只能来自第 3 节的新增项——那部分我没有预设答案；
- 独立模型跑的召回率可能显著低于此，尤其 N-1、N-2 这类需要跨三条规则推理的。

**可执行的验收方法**（等有 API key 时）：

1. 用 a1b 对 108 条规则跑一次，记录 `conflicts` 与 `questions`；
2. 与本文第 3 节 + 金标准 12 条比对，算召回；
3. 换一个模型再跑一次，比较两次结果的交集——**交集是稳定检出，差集是需要人工兜底的部分**；
4. 验收线：召回 ≥ 10/12、误报 ≤ 3 条。

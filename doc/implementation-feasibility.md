## 一、合并后的目标架构（取四源之长）

最有价值的合并点：**CSDN 的"接口依赖图谱" + 腾讯云的"代码图谱"是两层不同的图，必须都要。**

- **接口依赖图谱（业务级）**：登录→Token→建单→支付，是"用例能不能串起来"的基础（CSDN 原文："没有这个基础，Agent 只能生成孤立的、无意义的脚本"）
- **代码图谱（实现级）**：改了 `order_service.calculate_total` → 哪些 API 受影响，是"该回归哪些"的基础（腾讯云的 CodeGraph）

```
┌─ L0 交互层 ─────────────────────────────────────┐
│  Web UI（对话 + 项目管理）· REST API · CLI        │
└───────────────┬─────────────────────────────────┘
┌───────────────▼─────────────────────────────────┐
│ L1 意图层：Artifact/意图分类器 → Orchestrator 路由 │
└───────────────┬─────────────────────────────────┘
┌───────────────▼─────────────────────────────────┐
│ L2 调度层：Supervisor (LangGraph)                │
│   状态管理 · 子 Agent 上下文隔离 · HITL 审核门     │
└───────────────┬─────────────────────────────────┘
┌───────────────▼─────────────────────────────────┐
│ L3 能力层：专业 Agent + Skills 技能库              │
│   接口解析 Agent → OpenAPI 2.0/3.0/3.1           │
│   链路分析 Agent → 接口依赖图谱 + CodeGraph 代码图谱│
│   数据构造 Agent → 参数约束推断 + 规则引擎         │
│   用例生成 Agent → LLM + 模板引擎                 │
│   执行验证 Agent → 失败归因（代码/数据/环境）       │
│   质量分析 Agent → 覆盖率 + 测试缺口识别           │
└───────────────┬─────────────────────────────────┘
┌───────────────▼─────────────────────────────────┐
│ L4 执行层（标准化，不含 LLM — 关键设计）          │
│   pytest + httpx 执行 · Schemathesis 契约/fuzz    │
│   断言 / 数据驱动 / Allure 报告                   │
└───────────────┬─────────────────────────────────┘
┌───────────────▼─────────────────────────────────┐
│ L5 基础设施：MySQL + Redis + Celery + RAG 知识库   │
└─────────────────────────────────────────────────┘
```

### 三条不可妥协的设计原则

1. **L4 执行层绝不放 LLM**。LLM 只负责生成/规划，执行必须是确定性代码。这决定了"执行通过率"能不能控住
2. **子 Agent 上下文隔离，由 Supervisor 显式传递**（腾讯云原文的设计），保证每步可审计
3. **HITL 审核门在生成后、执行前**（MASTEST 论文的结论：错误会在管道中放大）

## 二、实现路线（四期，每期有交付物和门禁）

### P0：最小闭环（2 周）—— 先别碰多智能体

**做什么**：单个接口解析 Agent + 固定模板生成器，输入 OpenAPI，输出可执行的 pytest 文件，跑起来出 Allure 报告。

- 技术：FastAPI + pytest + httpx + Allure
- **验收门禁（必须全部达标才进 P1）**：
  - 对 1 个真实服务（≥20 个接口）生成脚本，**可执行率 ≥ 70%**
  - 脚本语法正确率 100%（MASTEST 论文实测可达）
  - 全流程无人工改代码即可跑通

> 这一步就是 TestGen AI 那个仓库**没做到**的部分。它只有 prompt 输出，没有 pytest 执行。

### P1：执行层标准化 + 数据构造（3 周）

**做什么**：
- 建**接口依赖图谱**（这是 CSDN 那篇强调的基石）：登录→Token→建单→支付
- 数据构造 Agent：从 OpenAPI Schema 推断约束 + 规则引擎补业务语义
- 失败归因：区分代码问题 / 数据问题 / 环境问题

- **验收门禁**：
  - 执行通过率 ≥ 85%
  - 依赖链路用例（≥3 跳）可自动串接执行
  - 失败用例自动归因准确率 ≥ 70%（人工抽检 50 条）

### P2：多智能体编排 + 审核门（3 周）

**做什么**：LangGraph Supervisor + 6 个专业 Agent（不是 9 个，见下方"不要做"）+ Agent Inbox 审核门

- **验收门禁**：
  - 子 Agent 上下文隔离生效，可回放每一步（LangSmith tracing）
  - 审核门：生成用例后暂停，Accept/Modify/Reject/Add 可用
  - **用例采纳率 ≥ 60%**（CSDN 建议的核心度量）

### P3：代码变更感知 + CI 门禁（4 周）

**做什么**：CodeGraph 接入，改代码→定位受影响 API→只跑相关测试；GitHub/GitLab PR 触发

- **验收门禁**：
  - 变更影响分析准确率 ≥ 80%（人工标注 20 次变更做对照）
  - 精准回归相比全量，**执行时间减少 ≥ 50%**
  - PR 触发后质量门禁可阻断合并

## 三、工作量与资源

| 阶段 | 工期 | 人力 | 备注 |
|---|---|---|---|
| P0 | 2 周 | 1 人 | 最关键的验证点 |
| P1 | 3 周 | 1 人 | 工作量最大，数据构造是难点 |
| P2 | 3 周 | 1 人 | 提示词调优占一半 |
| P3 | 4 周 | 1 人 | Java/Spring 路由识别需额外验证 |
| **合计** | **3 个月** | 1 人 | 2 人可压缩到 1.5-2 个月 |

**成本大头提示**：不是开发工时，是 LLM 调用成本和提示词调优时间。参考 ScrollTest 实测：Healer 用小模型做首轮、仅模糊故障升级大模型，**API 成本降 34%** —— 分级用模型是必须做的优化。

## 四、风险清单

| 级别 | 风险 | 对策 |
|---|---|---|
| 🔴 P0 | LLM 生成的用例看着对、跑不通 | L4 执行层不放 LLM；P0 阶段就用可执行率卡门禁 |
| 🔴 P0 | 跨语言：CodeGraph 对 Java/Spring 注解路由识别精度未验证 | P3 前必须拿真实 Java 微服务做一轮实测；不支持的框架直接跳过并标 `unsupported`（不降级兜底，见能力设计 v2.15） |
| 🟡 P1 | 测试数据不符合业务语义（订单-支付-库存链式依赖） | 规则引擎兜底 + 人工维护种子数据 |
| 🟡 P1 | Token 成本失控 | 分级用模型 + 每 run 硬上限 + 调用次数上限 |
| 🟡 P1 | 平台能调任意 base_url，存在生产事故风险 | 环境白名单 + 执行前审批 |
| 🟢 P2 | 上游依赖停更（CodeGraph/DeepAgents 均为活跃项目，风险较低） | 关键组件做版本锁定和 fork 兜底 |

## 五、明确"不要做"的三件事

1. **不要把 GitHub 那个 TestGen AI 仓库当起点**。`requirements.txt` 是空的、Gemini 客户端是 0 字节、没有一行执行代码。从零写比改它快
2. **不要一上来就做 9 个 Agent**。TestGen AI 的教训就在这：9 个 agent 全是空壳 prompt，没有一个能实际干活。**先做 1 个（接口解析+生成），跑通了再拆**
3. **不要跳过执行层直接做编排**。多智能体编排是最性感的部分，但如果没有 P0 的可执行率和 P1 的通过率打底，编排得再漂亮也只是在批量生产跑不通的脚本

---

## 六、结论

**能实现，但要按"先验证执行能力、再上编排"的顺序做，且不要指望现成源码。**

三个来源加一个仓库，真正能拿来用的是：**CSDN 那篇的四层模型当施工图 + 腾讯云那篇的 CodeGraph 思路当差异化 + MASTEST 论文的实测数据当验收基线**。GitHub 那个仓库的价值是反面的——它示范了"只有 prompt 没有执行层"会做成什么样。

建议第一步：花 2 周做 P0，拿一个真实的 OpenAPI（≥20 接口）跑到"可执行率 ≥70%"。**这一关过不了，后面三期都别投。**

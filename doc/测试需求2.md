三、文档说明

名词解释

术语
说明
合伙人
通过注册与审核、获得线索领取与签约权限的经纪人账号，对应 partners 表一行
有效签单
计入本月签单量的订单，状态限白名单 signed（已签约待服务）/ in_service（服务中）/ completed（已完成）

四、需求背景


























项内容需求来源合伙人招募线上化现状报名靠线下填表 + 人工录入，审核进度靠群里问，签单与收益靠人工核算痛点资料重复登记与身份证错录导致后续实名/结算失败；候选人反复询问审核进度消耗运营人力；新合伙人入驻后不知道先做什么；分成口径不一致产生争议不做的后果入驻规模上来后人工成本线性增长，且错录与口径争议会直接演变为结算纠纷

六、功能详细说明

6.1 产品流程图

[流程图链接]

注册主流程：进入 p-register → 第 1 步（姓名/手机号/验证码）→ 校验通过 → 第 2 步（城市/身份证/协议）→ 提交 → 幂等校验 → 写入 partners + 审核日志 → 跳 P-04

审核流转：pending/step1 → 受理 → step2 初审 → step3 复核 → approved/step4；任一步驳回 → rejected → 重新提交 → 回 pending/step1

工作台：登录 → 校验 audit_status=approved → 聚合接口取数 → 渲染身份/档位/四卡/待办/入口

6.2 功能说明（异常处理并入各功能点）

6.2.1 P-03 合伙人注册（p-register）














































#功能详细说明（正常逻辑 + 异常处理）1访问与分步未注册用户免登录可访问，表单分两步：第 1 步姓名/手机号/验证码，第 2 步城市/身份证/协议。异常：已通过审核者访问 → 重定向 p-home；待审核或被驳回者 → 重定向 p-audit；第 1 步未校验通过不许进第 2 步；中途退出，第 1 步数据不保留2姓名2–20 个字符，允许中文、字母、空格、·。异常：为空、纯符号、纯数字、超 20 字 → 输入框下方提示并阻止下一步，提示定位到该字段3手机号 + 验证码手机号 11 位、1 开头、第二位 3–9；验证码 6 位、5 分钟有效；同号 60 秒内不可重发，单号每日上限 10 次，单 IP 每小时 20 次，第 3 次获取起触发图形验证码。异常：验证码错误（累计 5 次作废需重新获取）、验证码过期、短信通道失败或 5 秒无响应提示稍后重试、命中频控按钮置灰显示倒计时、手机号已注册（未通过审核 → 引导去 P-04 看进度；已通过 → 引导登录）4所在城市枚举五选一：贵阳/成都/长沙/武汉/南京；必须显式选择，不设默认值。异常：未选 → 阻止提交并提示；配置下发为空 → 提示「城市列表加载失败」并禁止提交（不允许空提交兜底）5身份证号18 位，前 17 位数字、末位数字或 X/x，必须通过 GB 11643 校验位（ISO 7064 MOD 11-2）。异常：格式错、校验位错 → 提示核对；已被占用 → 返回与其他情况一致的通用提示「该证件信息暂无法完成注册，请联系客服」（禁止提示「该身份证已注册」以防枚举）；输入错误时不得把明文送进日志6合作协议《合伙人合作协议》默认未勾选，必须用户主动勾选；点击协议名可打开全文；提交时记录协议版本号、勾选时间、IP、UA。异常：未勾选 → 按钮不提交并高亮提示；打开全文时发现版本已更新 → 展示最新版并要求重新勾选；协议版本与勾选版本不一致时不许提交7提交注册提交前做前端全量校验 + 后端唯一性校验；以「手机号 + 身份证」为业务唯一键幂等；成功后写入 partners（status=pending、audit_status=pending、audit_step=1）并写一条审核日志，跳转 P-04。异常：连点 → 按钮立刻置 loading 并禁用，前端加锁，服务端幂等兜底（三次重复请求只产生一条记录、返回同一 partner_id、前端只跳转一次）；网络中断/超时 → 保留表单内容展示重试，重试沿用同一幂等键不产生重复档案

## 三、文档说明

### 名词解释

| 术语      | 说明                                                                      |
| ------- | ----------------------------------------------------------------------- |
| 合伙人     | 通过注册与审核、获得线索领取与签约权限的经纪人账号，对应 `partners` 表一行                             |
| 有效签单    | 计入本月签单量的订单，状态限白名单 `signed`（已签约待服务）/ `in_service`（服务中）/ `completed`（已完成） |
| 档位      | 按当月有效签单量匹配的佣金比例档，如 35%/40%，来源 `CONFIG.commissionTiers`                  |
| 分成 / 结算 | 单笔订单按签约时档位计算合伙人收益（`settlements.partner_commission`）；结算指分成从「待结算」转为「已结算」  |
| 冲正      | 因退单/纠纷/错算对已结算分成做反向记账，产生负向记录，必须从收益中扣除                                    |
| 冻结      | 用户发起提现到打款完成期间锁定的金额，必须从可提现中扣除，防重复提现                                      |
| 审核四步    | 提交资料 → 总部初审 → 资质复核 → 审核通过，对应 `audit_step` = 1/2/3/4                     |
| 自然月     | 时区 Asia/Shanghai，区间 `[当月 1 日 00:00:00, 次月 1 日 00:00:00)`，左闭右开           |

## 四、需求背景

| 项     | 内容                                                                   |
| ----- | -------------------------------------------------------------------- |
| 需求来源  | 合伙人招募线上化                                                             |
| 现状    | 报名靠线下填表 + 人工录入，审核进度靠群里问，签单与收益靠人工核算                                   |
| 痛点    | 资料重复登记与身份证错录导致后续实名/结算失败；候选人反复询问审核进度消耗运营人力；新合伙人入驻后不知道先做什么；分成口径不一致产生争议 |
| 不做的后果 | 入驻规模上来后人工成本线性增长，且错录与口径争议会直接演变为结算纠纷                                   |

## 六、功能详细说明

### 6.1 产品流程图

[流程图链接]

注册主流程：进入 p-register → 第 1 步（姓名/手机号/验证码）→ 校验通过 → 第 2 步（城市/身份证/协议）→ 提交 → 幂等校验 → 写入 `partners` + 审核日志 → 跳 P-04  
审核流转：`pending/step1` → 受理 → `step2` 初审 → `step3` 复核 → `approved/step4`；任一步驳回 → `rejected` → 重新提交 → 回 `pending/step1`  
工作台：登录 → 校验 `audit_status=approved` → 聚合接口取数 → 渲染身份/档位/四卡/待办/入口

### 6.2 功能说明（异常处理并入各功能点）

#### 6.2.1 P-03 合伙人注册（p-register）

| # | 功能        | 详细说明（正常逻辑 + 异常处理）                                                                                                                                                                                                                                            |
| - | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1 | 访问与分步     | 未注册用户免登录可访问，表单分两步：第 1 步姓名/手机号/验证码，第 2 步城市/身份证/协议。**异常**：已通过审核者访问 → 重定向 p-home；待审核或被驳回者 → 重定向 p-audit；第 1 步未校验通过不许进第 2 步；中途退出，第 1 步数据不保留                                                                                                                      |
| 2 | 姓名        | 2–20 个字符，允许中文、字母、空格、`·`。**异常**：为空、纯符号、纯数字、超 20 字 → 输入框下方提示并阻止下一步，提示定位到该字段                                                                                                                                                                                    |
| 3 | 手机号 + 验证码 | 手机号 11 位、1 开头、第二位 3–9；验证码 6 位、5 分钟有效；同号 60 秒内不可重发，单号每日上限 10 次，单 IP 每小时 20 次，第 3 次获取起触发图形验证码。**异常**：验证码错误（累计 5 次作废需重新获取）、验证码过期、短信通道失败或 5 秒无响应提示稍后重试、命中频控按钮置灰显示倒计时、手机号已注册（未通过审核 → 引导去 P-04 看进度；已通过 → 引导登录）                                                     |
| 4 | 所在城市      | 枚举五选一：贵阳/成都/长沙/武汉/南京；必须显式选择，不设默认值。**异常**：未选 → 阻止提交并提示；配置下发为空 → 提示「城市列表加载失败」并禁止提交（不允许空提交兜底）                                                                                                                                                                   |
| 5 | 身份证号      | 18 位，前 17 位数字、末位数字或 `X/x`，必须通过 GB 11643 校验位（ISO 7064 MOD 11-2）。**异常**：格式错、校验位错 → 提示核对；已被占用 → 返回与其他情况一致的通用提示「该证件信息暂无法完成注册，请联系客服」（禁止提示「该身份证已注册」以防枚举）；输入错误时不得把明文送进日志                                                                                            |
| 6 | 合作协议      | 《合伙人合作协议》默认未勾选，必须用户主动勾选；点击协议名可打开全文；提交时记录协议版本号、勾选时间、IP、UA。**异常**：未勾选 → 按钮不提交并高亮提示；打开全文时发现版本已更新 → 展示最新版并要求重新勾选；协议版本与勾选版本不一致时不许提交                                                                                                                               |
| 7 | 提交注册      | 提交前做前端全量校验 + 后端唯一性校验；以「手机号 + 身份证」为业务唯一键幂等；成功后写入 `partners`（`status=pending`、`audit_status=pending`、`audit_step=1`）并写一条审核日志，跳转 P-04。**异常**：连点 → 按钮立刻置 loading 并禁用，前端加锁，服务端幂等兜底（三次重复请求只产生一条记录、返回同一 `partner_id`、前端只跳转一次）；网络中断/超时 → 保留表单内容展示重试，重试沿用同一幂等键不产生重复档案 |

#### 6.2.2 P-04 合伙人审核状态（p-audit）

| # | 功能        | 详细说明（正常逻辑 + 异常处理）                                                                                                                                                                                                                                                                                          |
| - | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | 四步进度条     | 展示「提交资料 → 总部初审 → 资质复核 → 审核通过」，步骤态由 `audit_step`（1–4）与 `audit_status` 共同决定：1 提交资料完成、2 初审中、3 复核中、4 通过；驳回时停在驳回所在步骤并标红。**异常**：查不到审核记录 → 展示兜底页 + 客服入口并上报；`audit_step` 缺失 → 按 `audit_status` 兜底展示（pending 停在 1、approved 停在 4）并告警                                                                                 |
| 2 | 当前状态与预计时间 | 状态标签三态：审核中 / 已通过 / 已驳回。预计完成时间 = 提交时间 + 2 个工作日（按自然工作日顺延，展示到 18:00 前），已通过时改为展示实际通过时间。**异常**：提交距今超 5 个工作日仍未流转 → 页面展示加急提示与客服入口，同时推送运营待办；时间字段缺失 → 不展示预计时间，只展示状态                                                                                                                                                 |
| 3 | 驳回原因与重新提交 | 驳回时展示 `reject_reason`（审核员必填，≤200 字）与「修改资料重新提交」按钮；点击回到 p-register 第 2 步并预填原资料，身份证号需重新输入；重提成功后 `audit_status` 回 `pending`、`audit_step` 回 1、`submit_at` 刷新、`resubmit_count` +1，并新增一条带 resubmit 标记的审核日志。**异常**：驳回原因为空 → 兜底文案「资料不符合要求，请联系客服确认具体原因」并告警；重提超过 3 次 → 按钮置灰并提示联系总部运营；重提时只改城市等非关键字段，仍走同一套校验，不允许跳过身份证重输 |
| 4 | 轮询与自动解锁   | 进入页面拉取最新状态，停留期间每 30 秒轮询一次；状态变为 `approved` 时展示「审核通过，已开通权限」，3 秒倒计时后自动跳 P-05（可取消）。**异常**：轮询连续 3 次失败 → 停止轮询，保留最后状态并标注「数据更新于 HH:mm」并提供手动刷新；页面已打开但用户在 P-05 等其他页时，接口返回 403 由前端统一拦截跳回本页；已通过者访问本页 → 直接重定向 p-home                                                                                                    |

#### 6.2.3 P-05 首页工作台（p-home）

| # | 功能                | 详细说明（正常逻辑 + 异常处理）                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| - | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1 | 顶部身份与档位           | 展示合伙人姓名（脱敏：保留首字其余 `*`，如「张*」）与当前档位标签（如「35% 档」）；档位取 `commissionTiers` 中满足 `min_orders ≤ 当月有效签单数` 的最高档。**异常**：档位配置缺失或格式异常 → 兜底最低档并告警，禁止展示空标签；姓名超长（脏数据）→ 截断加省略号，不换行破坏布局                                                                                                                                                                                                                                                                                          |
| 2 | 数据卡：本月签单数 / 本月成交额 | 签单数 = 当月内 `partner_id` 匹配且状态命中白名单（`signed`/`in_service`/`completed`）的订单数，时间以 `orders.sign_at` 为准；成交额 = 同一订单集合的签约金额快照 `signed_amount` 之和，含未完成服务订单，不因退款冲减（退款影响体现在收益侧）。**异常**：跨月零点切换 → 按新自然月重算，档位可能回落，页面不提示但数据自动更新；聚合子查询超时 → 该卡片展示「暂不可用」，其余卡片正常渲染，支持下拉刷新；本月零单 → 展示 0 与引导文案「本月还没有签单，去领线索开始吧」                                                                                                                                                                     |
| 3 | 数据卡：累计收益 / 可提现金额  | 累计收益 = `settlements` 中 `settled` 的 `partner_commission` 之和 − `reversed` 冲正金额绝对值，`pending` 与 `void` 不计入；可提现 = 累计收益 − 提现中冻结（`withdrawals.status in applying/paying`）− 已打款（`paid`），结果 < 0 时展示 0.00。金额以「分」为最小单位存储计算（整数或 Decimal），禁止浮点；展示格式 `¥1,234.56`，千分位两位小数。计算逻辑服务端单一实现，首页与 P-26/P-27 复用同一函数。**异常**：可提现 < 0、可提现 > 累计收益、单合伙人金额日环比波动 > 50%、首页金额与台账对账差异 > 0.01 元 → 四类命中任一即告警并携带 `partner_id` 与上下文；金额 ≥ 1 亿 → 卡片展示「¥1.23 亿」，精确值进明细页看；聚合接口整体失败 → 整页兜底态 + 重试按钮，不上白屏 |
| 4 | 档位进度              | 展示「当前档位 → 距下一档还差 N 单」，文案如「再签 1 单升至 40%」；距下一档 = 下一档 `min_orders` − 当月签单数；已达最高档展示「已达最高档（45%）」且不显示剩余进度段。档位按月独立计算，每月 1 日 00:00:00 起按新自然月重算（读时计算，不依赖定时任务清零）；档位仅影响当月新签约订单的结算比例，已生成或已结算的分成比例不追溯修改。**异常**：当月签单 0 → 展示最低档；配置变更（档位数量减少）→ 按新配置重算，历史已结算记录不受影响                                                                                                                                                                                                            |
| 5 | 待办事项              | 三类待办：待跟进线索（分配给本人且状态 `assigned`/`following` 的线索数）、待安排面试（已匹配阿姨且 `interview_status=pending_schedule`）、待签约订单（已确定阿姨且 `order_status=pending_sign`）；每项展示数量并可点击跳转；数量为 0 时该项置灰展示「暂无待办」。**异常**：单个待办数据源超时 → 该项展示「—」并置灰不可点，其余正常；三类全为 0 → 待办区整体展示空状态引导                                                                                                                                                                                                                    |
| 6 | 快捷入口              | 四个入口：领线索（P-08）、找阿姨（P-11）、发起面试（P-18）、创建签约（P-21）；入口可见性受对应功能开关控制。**异常**：对应功能未上线 → 入口直接隐藏（禁止置灰占位、禁止点击后 404）；开关读取失败 → 按「隐藏」处理并上报，不允许默认全展示                                                                                                                                                                                                                                                                                                                         |
| 7 | 越权与状态守卫           | 所有接口从登录态解析 `partner_id`，禁止接受前端传入的 ID；非 `approved` 状态调用首页接口一律返回 403 且响应体不含任何金额字段。**异常**：手工拼接 URL 访问 p-home → 服务端 403 并前端重定向 p-audit；token 过期 → 统一跳登录页；`audit_status` 在会话期间被后台改为驳回 → 下一次接口调用返回 403 并引导去 P-04                                                                                                                                                                                                                                                   |

## 七、非功能需求

| 类别          | 要求                                                                         |
| ----------- | -------------------------------------------------------------------------- |
| 营销 / 运营     | 注册页需支持渠道来源标记（用于统计不同招募渠道的转化）；档位文案、活动 Banner 由运营配置                           |
| 财务          | 分成、冲正、冻结、可提现口径须与财务台账一致，支持 T+1 对账；金额单位统一为分                                  |
| 法务 / 合规     | 《合伙人合作协议》需版本化管理并可举证（版本号+时间+IP+UA）；身份证号属敏感个人信息，须单独告知处理目的与必要性；隐私政策入口必须在注册页可见 |
| 使用帮助 / 问题反馈 | P-04 与 P-05 均需提供客服入口（400-XXX-XXXX）；审核超期、金额异常时优先引导客服而非让用户自行猜测               |

### 7.1 技术约束

| 类别  | 要求                                                                                                                               |
| --- | -------------------------------------------------------------------------------------------------------------------------------- |
| 性能  | 首页聚合接口 P95 ≤ 500ms、P99 ≤ 800ms；p-home 首屏可交互 P95 ≤ 1.5s；p-register 首屏 P95 ≤ 1.2s                                                  |
| 容量  | 日注册提交 5,000 次、首页日活 20,000 人（人均 8 次/日），峰值按 3 倍余量设计（估算值）                                                                           |

| 安全  | 全站 HTTPS（TLS ≥ 1.2）；手机号、身份证号加密存储（AES-256-GCM 或国密 SM4），密钥 KMS 托管并与业务库分离；应用与网关日志对手机号、身份证号脱敏（保留前 3 后 4）；所有合伙人接口从登录态取身份，禁止信任前端传入的 ID |
| 可观测 | 注册漏斗、审核状态分布、首页接口错误率、金额对账差异四类指标接入监控，告警触达值班群                                                                                       |

## 八、埋点

| 参数名                           | 参数说明         | 参数值                                                                                                                                                                                            |

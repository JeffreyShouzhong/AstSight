# 业务确认单 · partner_onboarding（P-03 合伙人注册）

> 对应 `ruleset.md` v3 业务确认清单 5 项：Q-01 / Q-02 / Q-03 / D-01 / D-02
> 来源：`docs/design.md` 7.3 待业务确认
>
> **用法**：会前 1 天发给对应责任人；会上只做三件事——选选项、定责任人、定截止时间；
> 会后按第 3 节回写。开放式提问一律不带到会上。

## 0 先看一个数（决定这件事的优先级）

| 指标 | 现状 |
|---|---|
| 业务规则 | 67 条（A 级 100%） |
| 用例 | 22 条 |
| 被用例引用的规则 | 20 / 67（**30%**） |
| 5 项待确认涉及的规则 | BR-06、BR-07、BR-40、BR-41、BR-47、BR-54、BR-55、BR-66 |
| 上述规则被用例引用次数 | **全部为 0** |

**结论**：这 5 条就算全部确认完，也没有任何一条用例会去验证它。
确认的终点不是"业务点头"，而是「规则变有效 + 用例补上 + 断言写死」三者同时满足。
缺了补用例这一步，确认只是把未知从文档挪到了聊天记录里。

## 1 分流：按「谁能回答」分组，不要按编号顺序问

现在 5 条混了四种性质。一起发给同一个人，必然得到"我看看"。

| 组 | 项目 | 性质 | 该找谁 | 形式 |
|---|---|---|---|---|
| A | Q-01、Q-03 | 业务策略 | 产品负责人 + 运营 | 30 分钟会，现场拍板 |
| B | Q-02 | 外部契约 | 验证码供应商 + 安全 + 后端 | 书面问询，必须带回契约文档 |
| C | D-01 | 口径选择 | 产品 + 数据 | 会签，可异步 |
| D | D-02 | 性能基线 | 运维 / SRE | 书面给数，压测前交付 |

## 2 确认卡片（逐条）

### Q-01 单 IP 限流对 NAT / 共享出口的误伤

| 项 | 内容 |
|---|---|
| 当前默认 | 20 次 / 60 分钟，无白名单、无设备级限流（BR-07） |
| 选项 A | 维持现状（最少改动，风险自担） |
| 选项 B | 阈值提高到 100 次 / 小时（仍保留单号 10 次/日上限） |
| 选项 C | **维持阈值 + 运营商出口白名单**（推荐） |
| 选项 D | 改按设备指纹限流（需前端采集改造，成本最高） |
| 推荐理由 | C 不放宽风险面，只消除误伤；但依赖运维提供出口 IP 清单 |
| 选错的代价 | 阈值调低 → 真实用户被拦，工单上升；调高 → 等于对撞库放开 |
| 影响规则 / 用例 | BR-07 / 0 条（**确认后需补 ≥2 条**） |
| 责任人 | 产品 + 运维 |
| 截止 | 提测前 |
| 不回答的兜底 | 按 A 上线，同时挂"IP 维度拦截率 > 1% 告警"，事后按数据调阈值 |

### Q-02 图形验证码服务契约

| 项 | 内容 |
|---|---|
| 当前默认 | token 由外部服务签发，本服务只透传校验；示例环境接受任意非空 token（BR-40、BR-41、AS-03） |
| 必须拿到的字段 | 签发方、token 有效期、失败次数上限、错误码清单、是否一次性、重放策略、联调环境地址 |
| 选项 | 不是选择题，是**取数题**——拿不到就没有生产契约 |
| 选错的代价 | 示例环境 `CAPTCHA_INVALID` 分支不可达，该分支永远无法验证；上线后图形验证码形同虚设 |
| 影响规则 / 用例 | BR-40、BR-41 / 0 条（**确认后需补 2 条**，含伪造 token、过期 token） |
| 责任人 | 后端 + 安全 |
| 截止 | **生产联调前（最优先，唯一硬阻塞）** |
| 不回答的兜底 | 透传 + 任意非空放行，但提测报告必须标注"CAPTCHA_INVALID 分支未验证"，不得默认通过 |

### Q-03 同一 idempotency_key 携带不同请求体

| 项 | 内容 |
|---|---|
| 当前默认 | 返回 409 `IDEMPOTENCY_KEY_CONFLICT`（BR-54、BR-55） |
| 选项 A | **维持 409**（推荐） |
| 选项 B | 返回首次结果 200 |
| 选项 C | 覆盖更新首次档案 |
| 推荐理由 | B 会把客户端 bug 伪装成成功；C 与"业务唯一键"语义冲突，且已写入的数据无法回滚 |
| 真正要问的问题 | 不是"你想怎样"，而是**客户端收到 409 后能否正确提示用户并终止重试**（前端答） |
| 影响规则 / 用例 | BR-54、BR-55 / 0 条（**确认后需补 2 条**） |
| 责任人 | 产品 + 前端 |
| 截止 | 提测前（涉及已落库数据，越晚改越贵） |
| 不回答的兜底 | 按 A 执行，不回退 |

### D-01 频控窗口口径

| 项 | 内容 |
|---|---|
| 当前默认 | 最近 24 小时 / 最近 60 分钟滚动窗口，UTC，左闭右开（BR-47） |
| 选项 A | **滚动窗口 UTC**（推荐） |
| 选项 B | 自然日 / 自然小时（需明确时区，建议 Asia/Shanghai） |
| 推荐理由 | 滚动窗口对用户公平，且不引入时区依赖；改 B 会让所有跨零点用例重写 |
| 选错的代价 | 选 B 后必须处理夏令时/时区切换，且"每日 10 次"的边界断言全部作废 |
| 影响规则 / 用例 | BR-06、BR-07、BR-47 / 0 条（**确认后需补 3 条**，含跨窗口重置） |
| 责任人 | 产品 + 数据 |
| 截止 | 提测前 |
| 不回答的兜底 | 按 A 执行；窗口口径做成配置项，事后可调 |

### D-02 生产性能 SLA

| 项 | 内容 |
|---|---|
| 当前默认 | 示例基线：注册 p95 ≤ 200 ms、短信 p95 ≤ 100 ms，10 并发 60 秒窗口（BR-66） |
| 必须拿到的数 | 注册 p95/p99、短信 p95、峰值并发、压测环境规格 |
| 说明 | 示例基线只能当开发自测下限，不能当验收标准 |
| 影响规则 / 用例 | BR-66 / 0 条（**确认后需补 1 条压测用例**） |
| 责任人 | 运维 / SRE |
| 截止 | 压测前（不阻塞功能提测） |
| 不回答的兜底 | 性能报告只写"示例基线通过，生产 SLA 未验证"，不作为准出依据 |

## 4 不要混进业务确认会的三类问题

| 项 | 为什么不进这个会 | 正确去处 |
|---|---|---|
| GAP-01（P-04 状态机 2/3/4 未定义） | 是范围问题，不是策略问题 | 需求方补 P-04 文档 |
| AS-01（身份证加密算法与密钥轮换） | 安全架构决策 | 安全评审 |
| AS-02（协议元数据的审计角色授权） | 安全架构决策 | 安全评审 |

混进去的后果：业务方对技术问题无法回答，会议降级为"再约一次"，5 个真问题被一起拖住。

## 5 优先级排序（按阻塞强度，不按编号）

1. **Q-02** —— 唯一硬阻塞，且示例环境分支不可达，不确认就永远测不到
2. **Q-03** —— 涉及已落库数据，越晚改成本越高
3. **Q-01** —— 影响线上误伤，可先按默认上线 + 告警观察
4. **D-01** —— 可配置化，事后可调
5. **D-02** —— 压测前给数即可
